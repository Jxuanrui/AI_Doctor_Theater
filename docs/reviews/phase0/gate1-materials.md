## 一票否决检查

| 项 | LMD | lumenx | 自研轻管线（ffmpeg+脚本） |
|---|---|---|---|
| 端口仅绑本机 | ✓ 127.0.0.1:5679 | ✓ 127.0.0.1:17177/3008 | ✓（无服务） |
| 不须装 torch | ✓（node） | ✓（python 无 torch） | ✓ |
| 可加显式 AI 标识 | ✓ 水印文案可配（本机 ffmpeg 无 drawtext，用 subtitles 滤镜等效实现） | 未验证到导出环节 | ✓（ffmpeg subtitles/drawtext 可控） |
| key 暴露可低成本修复 | **N2：GET /ai-configs 明文返回 key**；修复=加鉴权中间件（上游未提供，需补丁） | key 在进程 env（不回显） | key 在 .secrets（不回显） |

→ 三者均无致命否决；LMD 的 N2 是最重风险项（需补丁或"用时才开"纪律缓解）。

## 结论建议（执行方，供监工终审与用户拍板）

- **监工倾向 LMD 的前提被实测推翻**：E9 三项能力中，字幕路径=TTS 绑死；**猫叫轨未证实可用**（merge_id=3 实测：零延迟相关性无法排除时移，RMS 与猫叫接近）——LMD 合成环两条路径均未证实可用，平台内实际跑通 4/6 环。
- 执行方建议：**LMD 仅作管理台**（项目/剧本/分镜——**成片一律禁用 LMD 导出**，只走自研 compose_episode.py）+ 自研 i2v_template + compose_episode（均已实战 corr 0.999663）；lumenx 暂停（出图适配成本高于收益）。Phase 1 复用两个已固化脚本，新增代码仅 P10 导出闸门（计划内）。
- 若用户坚持纯 LMD：需补 2-3 件补丁（N2 鉴权、尺寸表、合成解耦），估 0.5-1 天。
- 纯自研：丢 LMD 的项目管理 UI，脚本化亦可（Phase 1 脚本化成本最低但人工步骤多）。
